# บทที่ 6 — เงินเดือน

โมดูลเงินเดือนของ TEAS จัดการข้อมูลพนักงาน + รอบจ่ายเงินเดือนรายเดือน โดยคำนวณ
**ภาษีหัก ณ ที่จ่าย (ภ.ง.ด.1 ตาม ม.50(1))** และ **ประกันสังคม (ม.33)** ให้อัตโนมัติ
ทุกครั้งที่สร้างรอบจ่าย แล้วออกเอกสารราชการที่ต้องนำส่งให้ครบ — ภ.ง.ด.1, สปส.1-10,
50ทวิ รายพนักงาน และ ภ.ง.ด.1ก สรุปทั้งปี.

ก่อนเริ่มอ่านบทนี้ คุณควรมี:

- บัญชีที่มีสิทธิ์ `payroll.run.manage` (สร้าง/ลบรอบจ่าย), `payroll.run.post`
  (อนุมัติ + บันทึกบัญชี), `payroll.run.pay` (บันทึกจ่าย) และ `master.employee.manage`
  (จัดการข้อมูลพนักงาน) — ปกติเป็นชุดสิทธิ์ของ admin หรือ Chief Accountant
- ข้อมูลบริษัท (บทที่ 2) ตั้งค่าแล้ว — ใช้พิมพ์ในหัวเอกสาร ภ.ง.ด.1 / ภ.ง.ด.1ก / สปส.1-10
- พนักงานอย่างน้อย 1 คนที่สถานะ active พร้อมตั้งเงินเดือนไว้แล้ว ก่อนสร้างรอบจ่ายแรก

## ในบทนี้

| Walkthrough | เรื่อง |
|---|---|
| 06.01 | รอบจ่ายเงินเดือน — สร้าง → อนุมัติ → บันทึกบัญชี → จ่าย พร้อม ภ.ง.ด.1 + ประกันสังคม |

> หน้า "ตั้งค่า → พนักงาน" (สร้าง/แก้ไขพนักงาน) และปุ่มเอกสารรายพนักงาน (50ทวิ,
> สลิปเงินเดือน) ยังไม่มี walkthrough แยกต่างหาก — ภาพหน้าจอ: 🚧 capture รอบถัดไป
> เนื้อหาด้านล่างอธิบายละเอียดจากตัวระบบจริงไปก่อน.

## แนวคิดที่ควรรู้ก่อนเริ่ม

### พนักงาน (Employee Master) — ตั้งค่าก่อนคำนวณเงินเดือนได้

ไปที่ **ตั้งค่า → พนักงาน** ก่อนใช้งานเงินเดือนครั้งแรก แต่ละคนต้องกรอกข้อมูลกลุ่มนี้:

| กลุ่มข้อมูล | ฟิลด์ | ใช้ทำอะไร |
|---|---|---|
| ข้อมูลพื้นฐาน | รหัสพนักงาน, ชื่อ-นามสกุล (ไทย/อังกฤษ) | ระบุตัวตนในสลิป/รายงาน |
| ภาษี | เลขบัตรประชาชน 13 หลัก (ระบบ validate ครบ 13 หลักก่อนบันทึกได้) | ออก 50ทวิ / ภ.ง.ด.1ก |
| เงินเดือน | เงินเดือนพื้นฐาน, วันที่เริ่มงาน | ฐานคำนวณ + จำนวนงวดที่เหลือของปี (ใช้ annualize ภาษี) |
| ลดหย่อน | สถานภาพสมรส, คู่สมรสมีเงินได้หรือไม่, จำนวนบุตร | ลดหย่อนส่วนตัว/คู่สมรส/บุตรตาม ม.47 |
| ประกันสังคม | checkbox "อยู่ในระบบประกันสังคม (ม.33)" | เปิด/ปิดการหักปกส. เป็นรายคน |
| ธนาคาร | ชื่อธนาคาร, เลขที่บัญชี | หลักฐานการจ่าย/สลิปเงินเดือน |
| ที่อยู่ | เลขที่, ถนน, ตำบล, อำเภอ, จังหวัด, รหัสไปรษณีย์ | พิมพ์ในแบบ ภ.ง.ด.1ก (สรุปภาษีรายปี) |

พนักงานที่ถูกปิดใช้งาน (deactivate) จะไม่ถูกดึงเข้ารอบจ่ายรอบใหม่อีก แต่ประวัติ
เงินเดือนเดิมในรอบที่ผ่านมายังอ้างอิงได้ตามปกติ.

### รอบจ่ายเงินเดือน (Payroll Run) — วงจรสถานะ

แต่ละงวดเดือนคือ **"รอบจ่าย" (Payroll Run)** หนึ่งรอบ ไหลผ่าน 4 สถานะตามลำดับ:

**ฉบับร่าง → อนุมัติแล้ว → บันทึกบัญชีแล้ว (Post) → จ่ายแล้ว**

1. **สร้างรอบจ่าย** (ปุ่ม "สร้างรอบจ่าย" มุมขวาบนของหน้ารายการ) — กรอก:
   - **งวดเดือน** รูปแบบ ค.ศ.ปปปปดด 6 หลัก (เช่น `202607`) — ระบบ prefill เป็นเดือน
     ปัจจุบันให้อัตโนมัติ พิมพ์ผิดรูปแบบหรือเดือนนอกช่วง 01–12 จะขึ้นข้อความเตือนทันที
   - **วันที่จ่าย** — prefill เป็นวันสิ้นเดือนของงวดนั้น มี hint วันที่แบบ พ.ศ. กำกับใต้ช่อง
   - กด "สร้าง" → ระบบ **ดึงพนักงานที่ยัง active และทำงานอยู่ในงวดนั้นเข้ารอบอัตโนมัติ**
     พร้อมคำนวณเงินได้ / ภาษีหัก ณ ที่จ่าย / ประกันสังคมให้ทันที — ไม่ต้องคีย์ทีละคน
   - **งวดเดือนเดียวกันสร้างรอบจ่ายซ้ำไม่ได้**
2. **อนุมัติ** (สิทธิ์ `payroll.run.post`) — ตรวจสอบตัวเลขในรอบก่อนล็อก
3. **บันทึกบัญชี / Post** (สิทธิ์ `payroll.run.post`, มีข้อความยืนยันก่อนกด) — ระบบสร้าง
   **สมุดรายวัน (JE) + ออกเลขที่เอกสารให้รอบจ่าย** และ **ล็อกแก้ไขไม่ได้อีก** ตั้งแต่ขั้นนี้
   เหมือนเอกสารประเภทอื่นในระบบ (ดูหลักการ Document Immutability ในบทที่ 1)
4. **จ่ายแล้ว** (สิทธิ์ `payroll.run.pay`, มีข้อความยืนยันก่อนกด) — บันทึกว่าโอนเงินเดือน
   ให้พนักงานเรียบร้อยแล้ว

**ลบได้เฉพาะรอบสถานะฉบับร่าง** เท่านั้น — ปุ่ม "ลบ" มีข้อความยืนยันสีแดง (destructive)
กันลบพลาด รอบที่อนุมัติหรือบันทึกบัญชีแล้วจะไม่มีปุ่มลบให้เห็นอีก.

### ภาษีหัก ณ ที่จ่าย — คำนวณแบบเฉลี่ยทั้งปี (ม.50(1))

ระบบคำนวณ ภ.ง.ด.1 ต่อพนักงานแบบ **annualize** ตามมาตรา 50(1): นำเงินได้งวดนี้
**เทียบเป็นรายปีตามจำนวนงวดจ่ายที่เหลือของปี** แล้วหักลดหย่อนส่วนตัว/คู่สมรส/บุตร
ตามข้อมูลพนักงาน คำนวณภาษีตามขั้นบันได แล้วหารกลับเป็นภาษีของงวดนี้.

> ⚠️ **ข้อควรระวัง — พนักงานที่เริ่มงานระหว่างปีมักเสียภาษี 0**
>
> เพราะจำนวนงวดจ่ายที่เหลือของปีน้อยกว่า 12 เงินได้ทั้งปีที่ annualize จึงอาจยังไม่ถึง
> เกณฑ์เสียภาษีหลังหักลดหย่อน แม้เงินเดือนจริงจะดูสูง — ไม่ใช่ระบบคำนวณผิด คลิกที่แถว
> พนักงานเพื่อเปิด breakdown (หัวข้อถัดไป) ระบบจะมีคำอธิบายเหตุผลกำกับไว้ในหน้าต่างเดียวกัน.

### ประกันสังคม (ม.33)

พนักงานที่ติ๊ก "อยู่ในระบบประกันสังคม" จะถูกหัก **5% ทั้งฝั่งลูกจ้างและนายจ้าง**
โดยมี **เพดานเงินเดือนที่นำมาคิด 17,500 บาท/เดือน** → หักสูงสุด **875 บาท/เดือน/ฝั่ง**
เงินเดือนที่เกินเพดานจะหักเท่ากับเพดานเสมอ ไม่ได้หักตามเงินเดือนจริงทั้งหมด.

### รายละเอียดรายพนักงานในรอบ (breakdown)

**คลิกที่แถวพนักงาน** ในตารางของรอบจ่ายเพื่อเปิดหน้าต่าง breakdown แสดง:

- เงินได้เสียภาษี / เงินได้ไม่เสียภาษี
- ภาษีหัก ณ ที่จ่าย (ภ.ง.ด.1)
- ประกันสังคมฝั่งลูกจ้าง (และฝั่งนายจ้าง ถ้ามากกว่า 0)
- รับสุทธิ
- กล่องข้อความท้ายหน้าต่าง อธิบายหลักการคำนวณแบบ annualize ตาม ม.50(1) —
  เหตุใดพนักงานที่เริ่มงานระหว่างปีอาจเสียภาษี 0 ทั้งที่เงินเดือนถึงเกณฑ์

**พนักงานที่ยังไม่ได้ตั้งเงินเดือน** (เงินได้ = 0) จะมี badge เตือน
**"ยังไม่ได้ตั้งเงินเดือน"** ใต้ชื่อในตาราง กดแล้วพาไปหน้าตั้งค่าพนักงานได้ทันที
และถ้า **ทั้งรอบมียอดสุทธิรวมเป็น 0** ระบบจะมี banner เตือนเหนือตาราง ให้ตรวจสอบเงินเดือน
พนักงานที่ ตั้งค่า → พนักงาน ก่อนกดอนุมัติ.

### เอกสารราชการหลังบันทึกบัญชี

เมื่อรอบจ่ายอยู่ในสถานะ "บันทึกบัญชีแล้ว" ขึ้นไป ปุ่มออกเอกสารจะปรากฏให้ใช้งาน:

| เอกสาร | ระดับ | รูปแบบ |
|---|---|---|
| ภ.ง.ด.1 (นำส่งภาษีหัก ณ ที่จ่ายของพนักงาน) | ทั้งรอบ | PDF |
| สปส.1-10 (นำส่งประกันสังคม) | ทั้งรอบ | .txt (ไฟล์นำส่ง) + PDF |
| สลิปเงินเดือน | รายพนักงาน | PDF (ปุ่มในแถว) |
| 50ทวิ (หนังสือรับรองหัก ณ ที่จ่ายรายปี) | รายพนักงาน | PDF (ปุ่มในแถว หลัง Post) |
| ภ.ง.ด.1ก (สรุปภาษีหัก ณ ที่จ่ายทั้งปี) | ทั้งปี | PDF — ปุ่ม + ช่องกรอกปีภาษี (ค.ศ.) อยู่หน้ารายการรอบจ่าย |

### สิทธิ์การเข้าถึงหน้าเงินเดือน

| หน้า | URL | ต้องมีสิทธิ์ |
|---|---|---|
| ตั้งค่าพนักงาน (สร้าง/แก้ไข/ปิดใช้งาน) | `/settings/employees` | `master.employee.manage` |
| รายการรอบจ่าย + สร้างรอบจ่ายใหม่ | `/payroll` | `payroll.run.manage` |
| รายละเอียดรอบจ่าย (อนุมัติ/บันทึกบัญชี/จ่าย/ลบ) | `/payroll/[id]` | `payroll.run.post`, `payroll.run.pay` ตามปุ่ม |

ผู้ใช้ที่ไม่มีสิทธิ์เขียน (เช่นมีแค่สิทธิ์ดู) จะเห็นข้อมูลได้ตามปกติแต่ปุ่มสร้าง/แก้ไข/
อนุมัติ/บันทึกบัญชี/จ่าย/ลบจะถูกซ่อนไปตามชุดสิทธิ์ที่ได้รับ — ดูภาพรวม role × สิทธิ์
ทั้งหมดได้ใน *คู่มือสิทธิ์การมองเห็น (RBAC UI Guide)*.

## เริ่มต้นใช้งานเงินเดือน

1. ตั้งค่าพนักงานทุกคนให้ครบก่อน (ตั้งค่า → พนักงาน) — โดยเฉพาะเงินเดือน, สถานะสมรส/บุตร
   และ ปกส. เพราะกระทบตัวเลขภาษี/ประกันสังคมโดยตรง
2. ไปหน้า **เงินเดือน** → กด "สร้างรอบจ่าย" — ดู Walkthrough 06.01 ประกอบขั้นตอน
3. ตรวจตัวเลขในรอบ (คลิกแถวพนักงานดู breakdown ถ้าตัวเลขดูผิดปกติ หรือเห็น badge
   เตือนพนักงานเงินได้ 0) → อนุมัติ → บันทึกบัญชี → จ่าย
4. ดาวน์โหลด ภ.ง.ด.1 และ สปส.1-10 ไปนำส่งหน่วยงานที่เกี่ยวข้องภายในกำหนด, แจกสลิป
   เงินเดือนให้พนักงาน และเก็บ 50ทวิ ไว้ออกให้พนักงานตอนสิ้นปีภาษี
