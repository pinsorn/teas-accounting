### Q1 — บริการออนไลน์ B2C ออกใบกำกับภาษีอย่างย่อได้ไหม → **ได้** (confidence: สูง)
ม.86/6 + ประกาศ VAT ฉบับที่ 32 ข้อ 2 ("การให้บริการรายย่อยแก่บุคคลจำนวนมาก" — รายการตัวอย่าง
เปิดด้วย "เป็นต้น") และแนววินิจฉัยตรง: **กค 0706/พ./830** (subscription TV แก่สมาชิกจำนวนมาก
ชำระออนไลน์ = เข้าเกณฑ์, rd.go.th/30777.html). ราคาต้องแสดงแบบรวม VAT. บริการเจรจาราคาราย
ลูกค้า/ลูกค้าน้อยรายอาจไม่เข้า — fallback: ขออนุมัติเฉพาะรายตาม ม.86/7. ทั้งสองแหล่งตรงกัน.

### Q2 — ออกด้วยซอฟต์แวร์ ต้องขอ ภ.พ.06 ไหม → **ไม่ต้อง ถ้าไม่ใช่ "เครื่องบันทึกการเก็บเงิน"** (confidence: กลาง — จุดเทาที่เหลืออยู่จุดเดียว)
- ม.86/6 ผูก approval กับ "ผู้ประสงค์จะใช้เครื่องบันทึกการเก็บเงิน" เท่านั้น; ประกาศ VAT ฉบับที่ 89
  ข้อ 7(2)-(3) แยก "อย่างย่อเป็นเล่ม/ไม่เป็นเล่ม" ออกจาก "จากเครื่องบันทึกการเก็บเงิน" ชัด →
  อย่างย่อไม่บังคับต้องมาจากเครื่อง; กค 0811/พ.5106: ใบกำกับ (เต็ม) ทำด้วยคอมพิวเตอร์ไม่ต้องขอ.
- จุดเทา: ฉบับที่ 46 นิยาม "เครื่องชนิดคอมพิวเตอร์" กว้าง — ระบบที่**รับชำระเงิน+ออกใบอัตโนมัติ**
  แบบ POS อาจถูกตีความเข้า (AGY เอียงทางนี้, Codex ชี้ว่าถ้อยคำเก่า คลุม cloud ไม่ชัด). ถ้าเข้าข่าย
  แล้วไม่ขอ: โทษ ม.90/3(2) (จำคุก ≤6 ด. / ปรับ ≤10,000).
- **ท่าที่แนะนำ**: TEAS ออกเอกสารแบบระบบบัญชี/invoicing (ผู้ใช้กดออก หรือ API สั่งออกเป็นรายการ)
  ไม่ใช่ POS รับเงินหน้าร้าน → ยืนตำแหน่ง "ไม่ใช่เครื่องบันทึกการเก็บเงิน" พร้อมบันทึกเหตุผล;
  ถ้าจะ auto-issue ผูกกับ payment gateway จริงจัง ให้ Ham เลือก: (ก) ยื่นหารือ/ภ.พ.06 กันเหนียว
  หรือ (ข) รับ residual risk (โทษระดับเล็ก, ไม่กระทบ VAT เอง). ⚠ ถ้าอนาคตทำ e-Tax Invoice:
  คนละระบบ — ยื่น บ.อ.01 (ประกาศ 7 มิ.ย. 2566).

### Q3 — รายการบนใบอย่างย่อ + ชื่อปลอมบนใบเต็ม → **อย่างย่อไม่ต้องมีข้อมูลผู้ซื้อเลย; ใบเต็มชื่อไม่จริง = โทษปรับ ≤2,000/ฉบับ ไม่ใช่คดีอาญาโดยอัตโนมัติ**
- อย่างย่อ (ม.86/6(1)-(7) + ฉบับที่ 45: ต้องมีคำว่า "อย่างย่อ" ต่อท้าย "ใบกำกับภาษี"): ผู้ขาย+
  เลขภาษี, เลขที่, รายการ, ราคา**รวม VAT**+ข้อความระบุ, วันที่. **ไม่มีช่องผู้ซื้อ**. (+เลขรหัส
  เครื่อง เฉพาะกรณีออกจากเครื่องที่ขออนุมัติ)
- ขอใบเต็มทีหลัง: ออกใบเต็ม (ม.86/4) "ออกแทนใบกำกับภาษีอย่างย่อ เลขที่..." ลงวันที่ตามจุดภาษีเดิม
  ไม่นับยอดซ้ำ (ฉบับที่ 89 ข้อ 7(4)(ข)); e-Tax ไม่ต้องเรียกคืนฉบับย่อ (กค 0702/443, 27 ม.ค. 2568);
  ลูกค้าต้องให้ชื่อ-ที่อยู่จริง (ม.86/4(3)) — ซึ่งเขาจะให้เองเพราะอยากได้ใบไปใช้.
- ชื่อ/username ไม่จริงบนใบเต็ม: Fable ตัดสินตาม **Codex** — รายการสาระสำคัญไม่ถูกต้อง = ปรับ
  ≤2,000/ฉบับ (ม.90(12)) + ผู้รับใช้เป็นภาษีซื้อไม่ได้ (ม.82/5(2), กค 0702/พ./131). โทษหนัก
  ม.90/4/86-13 (ที่ AGY ยก) ต้องมี**เจตนา**ฉ้อโกง/เลี่ยงภาษี — ไม่ใช่กรณีลูกค้าพิมพ์ชื่อเอง
  โดยผู้ขายสุจริต. AGY overstated ข้อนี้ (รวม element เจตนาเข้าไปโดยไม่แยก).

### Q4 — non-VAT: ใบรับ → **ไม่ต้องมีชื่อลูกค้า B2C; เกณฑ์บังคับออก = รับเงินเกิน 100 บาท/ครั้ง**
- ม.105ทวิ รายการขั้นต่ำ: เลขภาษี+ชื่อผู้ออก, เลขที่/เล่ม, วันที่, จำนวนเงิน (+รายละเอียดสินค้า
  เฉพาะการขายสินค้า ≥100฿ — ไม่บังคับกับ "บริการ"). **ชื่อผู้ซื้อบังคับเฉพาะขายส่งให้ผู้ค้า
  ประเภทเดียวกัน (B2B supply chain)** — ไม่ใช่กรณีเรา. เก็บสำเนา ≥5 ปี.
- เกณฑ์: **เกิน 100 บาทต่อการรับเงินแต่ละครั้ง** สำหรับกิจการยกเว้น VAT — ยืนยันจากตัวประกาศ
  อากรแสตมป์ **ฉบับที่ 34 ข้อ 1** โดยตรง (Fable fetch rd.go.th/3435.html). AGY's ">10,000" ผิด
  (อ้างฉบับ 28/49 ที่ตัวเองติดธงว่าไม่ได้ยืนยัน — ธงแม่น). งวดผ่อนของยอดเดียวกัน: ออกทุกงวด.
- กฎหมายไม่มีเอกสารชื่อ "ใบรับอย่างย่อ" — มันคือ "ใบรับ" ธรรมดาที่ไม่มีชื่อลูกค้า ซึ่งถูกกฎหมายอยู่แล้ว.

## IMPLICATIONS สำหรับ TEAS (คำตอบต่อคำถาม Ham "ไม่ทำอย่างย่อได้ไหม")
1. **Non-VAT co: ไม่ต้องเพิ่ม doc type ใหม่ตามกฎหมาย** — ใบรับปัจจุบันโดยไม่มีชื่อจริง/ที่อยู่ = ชอบ
   ด้วย ม.105ทวิ. งานที่อาจเหลือเป็น OPERATIONAL เท่านั้น (ลูกค้า generic "ลูกค้ารายย่อย",
   ทางลัดออกใบรับ standalone สำหรับ volume) — ไม่ใช่ compliance.
2. **VAT co: ใบเต็มชื่อตามที่ลูกค้าพิมพ์+ไม่มีที่อยู่ = เสี่ยงปรับ ≤2,000/ฉบับ** (ไม่ใช่อาญา) + ระบบ
   สะสมใบบกพร่องทุกการขาย. **ใบอย่างย่อแก้ปัญหานี้ตรงตัว** (ไม่มีช่องผู้ซื้อโดยนิยาม) และมี
   precedent ตรง (กค 0706/พ./830). จุดเทาเดียวคือ ภ.พ.06 ถ้า auto-issue แบบ POS-like.
3. ทางสายกลางที่ scope เล็กสุดถ้ายังไม่อยากทำอย่างย่อ: ใบเต็มออกเฉพาะเมื่อลูกค้า**ขอ**และ**กรอกข้อมูล
   จริงเอง** (บังคับ field), การขายปกติบันทึกรายรับโดยไม่ออกใบกำกับต่อรายการ — แต่ผิด ม.86 (VAT
   registrant ต้องออกใบกำกับทุกการขาย) → **ไม่ใช่ทางเลือกที่ถูกกฎหมาย**. สรุป: VAT co เลือกได้แค่
   (ก) ใบเต็มพร้อมยอมรับ defect-fine risk หรือ (ข) ทำใบอย่างย่อ.

## ✅ HAM RULED (2026-08-21) — SCOPE CLOSED, ZERO BUILD
- **VAT co: เก็บชื่อจริง+ที่อยู่จริงของลูกค้าตอนขาย แล้วออกใบกำกับภาษีเต็มรูปตามปกติ** — เลือก
  compliance ทาง checkout form แทนการเพิ่ม doc type. ถูกกฎหมายเต็ม (ม.86/4 ครบ), ไม่มี scope ใหม่.
- **Non-VAT co: ใช้ใบรับ flow เดิม** — ถูกกฎหมายอยู่แล้ว (ชื่อลูกค้าไม่บังคับ B2C).
- ใบกำกับอย่างย่อ: NOT BUILT — YAGNI. Note นี้เก็บไว้เป็น reference ถ้าอนาคตเปลี่ยนใจ (verdicts +
  precedents ยังใช้ได้; จุดเดียวที่ต้องระวังเมื่อกลับมา = ภ.พ.06 gray zone ใน Q2).
- Implementation note ฝั่งระบบขายออนไลน์ (นอก TEAS): checkout ต้องบังคับกรอกชื่อจริง+ที่อยู่;
